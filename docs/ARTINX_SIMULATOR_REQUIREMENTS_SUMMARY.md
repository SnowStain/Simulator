# ARTINX Simulator 需求与推进总结

更新时间：2026-05-08

本文档汇总本轮连续开发中已经明确的目标、规则约束和后续维护原则，方便后续开发者或 AI 接着推进。

## 房间与对局流程

- 删除旧 5v5 选车大厅链路，统一为房间大厅和局内准备阶段。
- 房间大厅不再承担兵种/构型选择，只负责创建房间、加入座位、添加玩家或 AI。
- 局内准备阶段选择出生点、兵种和构型；单人模式准备 60s，可按 Enter 跳过。
- 本地模式需要 15s 裁判系统自检时间；准备和自检期间都可以打开 P/O 类面板。
- 登出返回房间页或主菜单，不再回旧大厅；Esc 不应直接返回大厅。
- 添加机器人、添加 AI、切换点位、切换构型不能触发地图和外观完整重载。

## 实体与 AI

- 添加了多少机器人，局内就只能存在多少机器人。
- 未启用机器人必须从 `World.Entities`、HUD、小地图、碰撞、弹丸、网络快照和 AI 控制中彻底排除，不能只隐藏。
- 玩家只能控制一个机器人。死亡后不切视角，画面灰度化并显示复活读条。
- 复活后需要去己方补给区解锁枪管，并带有无敌与虚弱状态。
- AI 寻路不能通过非指定的一二级台阶、飞坡段和高落差区域；AI 路径规划必须限流并复用路径，不能造成帧率卡顿。

## LAN 联机

- 主机是权威模拟端，客户端发送输入、配置和选择，接收权威快照。
- 客户端和主机必须看到一致实体数量、位姿、云台方向、pitch/yaw 和子弹状态。
- 开始游戏后客户端输入不能闪回，主机端必须能看到客户端机器人实体和位姿变化。
- 日志需要覆盖 roster、snapshot、input、digest、pose drift、实体数、上下行速率和丢包/延迟。
- P 面板在 LAN 准备、自检和对局内都可打开并可关闭；隐藏后必须禁用鼠标交互区域。

## UI 与 HUD

- 本地模式玩家使用 `O` 面板，功能照搬 LAN 裁判端 `P` 面板。
- 局内顶部 UI 显示当前基地/前哨站血量数字，数字层级必须高于血条填充。
- 无控制源机器人不显示顶部栏；小地图只显示真实存在的机器人。
- 受击第一视角四周显示淡红渐变闪动。
- 死亡后提示层级在最上层，背景保持黑白灰直到复活。
- 英雄吊射 UI 和能量机关自瞄 UI 需要保持可读，按住右键时不应变黑或丢失关键提示。

## 地图、加载与碰撞

- 地图资源、runtime grid、appearance catalog 和设施标注应在进入完整游戏进程时预加载并复用。
- 进入同一局后，座位、出生点和构型变化不应重复加载地图。
- `map.json`/component roles 过大时必须拆分，并确保加载器支持分片入口。
- 地图编辑器新增的 collision 体积必须进入局内碰撞和调试显示。
- collision 与 buff 都应使用立体结构，支持 xyz、ypr、长宽高、半径和高度。
- 手动碰撞体积高度必须按编辑器设定完整映射，不能被压成薄片或堆在地图下方。
- 可通过地形先判定垂直落差，再判定水平通过性；麦轮最高可爬升高度 25cm。

## 机器人移动与碰撞

- 机器人碰撞尽量与 GPU 渲染看到的外观一致，并随车体、云台、腿部、轮子、连杆姿态变化。
- 平衡步兵轮子应是横向圆柱，连杆碰撞应贴合视觉连杆。
- 平衡步兵不能穿墙，也不能平地振动卡死；需要在旧提交移动性和新版本严格性之间折中。
- 弹丸反弹只用于合理的地面、墙面和车体效果；基地、前哨站、能量机关等精密结构命中后不再把弹丸反弹进模型内部。

## RMUC 规则

- 基地血量低于 2000 后外板展开，参考 `规则/基地建模/3.png`。
- 当前实现要求精细地形外板按原始局部坐标相对初始位置移动，并在动态渲染阶段提供粗模展开兜底。
- 基地中部左右装甲板需要可命中、可提示、可被英雄吊射自瞄识别。
- 前哨站、基地血量机制按 `规则/血量机制.png` 对齐。
- 堡垒占领需要读条；己方占领与对方占领效果不同，并提供额外弹药显示。
- Buff 区按 `规则/增益` 对齐，F3 显示处于区域时必须能触发。
- 补给区用于复活后的枪管解锁。

## 能量机关

- 小能量机关和大能量机关都按 `规则/能量机关` 目录实现。
- 小能量机关待激活时只显示盘面待激活标志；命中激活后才高亮灯臂。
- 大能量机关一次亮两个盘，命中任意一个后进入补击窗口并显示进度。
- 待激活圆盘样式参考规则图 5-21，但颜色按对应阵营显示。
- 能量机关自瞄需要对旋转盘做自适应前馈预测；高速目标根据观测角速度提高 lead。
- 按住右键进入能量机关自瞄时，在最佳位置自动扳机；Q 能量机关模式发射频率不超过 25Hz。
- 小弹丸命中判定需要容忍盘面高速运动与画面/模拟延迟，避免“看起来命中但不点亮”。

## 性能体系

- P 面板中的底盘类型和发射机构类型用于配置性能体系，不用于改车型。
- 步兵：底盘类型为血量优先/功率优先；发射机构为爆发优先/冷却优先。
- 英雄：底盘和发射机构指向同一配置，近战优先/远程优先。
- 工程：只显示底盘类型，不显示发射机构。
- 其他无差异配置显示默认。
- 升级和配置改动血量时按比例调整当前血量，不保持旧绝对值。

## 渲染与加载管线约束

- 新增渲染模式接 `Simulator3dForm.Pipeline.cs` 的 mode/context/frame/render pass 计划。
- 新增地图标注接 `ComponentAnnotationImporter/Exporter` 和 `FineTerrainAnnotationDocument`。
- 新增碰撞体积接 `RuntimeGridData`、`TerrainMotionService` 和 `ProjectileObstacleResolver`。
- 新增精细地形视觉接 `FineTerrainVisualCache`、GPU 动态批次和 CPU 兜底绘制。
- 新增机器人几何先扩展 `RobotAppearanceProfile`，避免视觉、碰撞和编辑器三套数据分叉。
- 新增 HUD/面板交互必须走现有 overlay/input 管线，隐藏时同步禁用交互命中。

## 验证要求

- 常规构建：`dotnet build src\Simulator.ThreeD\Simulator.ThreeD.csproj -c Debug --no-restore`
- 启动器同步：`robocopy "src\Simulator.ThreeD\bin\Debug\net10.0-windows" "build_verify\launcher_builds\debug\threeD" /E /R:1 /W:1 /NFL /NDL /NJH /NJS /NP`
- 手测重点：基地 2000 以下展开、能量机关命中点亮、O/P 面板打开关闭、collision 高度映射、LAN 客户端输入和主机位姿一致。
